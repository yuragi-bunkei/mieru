# mieru — STLライブビューア 設計書

日付: 2026-08-01
状態: ユーザー承認済みの方針（案B: 自作ライブビューア）を設計に落としたもの

## 目的

Claude Codeで3Dプリント用モデリング（主にPythonスクリプト→STL出力）をするとき、
出力STLを常時表示し、ファイル更新の瞬間に自動リロードするビューアを提供する。
Claude Codeデスクトップアプリの**Browserペイン**に表示して、コード操作とプレビューを
並べて確認できるようにする。Claude自身もスクリーンショットで形状を自己検証できる。

## スコープ

- 対象: 任意のプロジェクトの出力STLディレクトリを監視して表示する汎用ツール
- 非対象: モデリング機能そのもの（編集・ブーリアン等）、STL以外の形式（3MF等は将来課題）、
  Tailscale等での外部公開（ローカル専用）

## 全体構成

```
~/dev/mieru/
├── server.js          # Nodeサーバー（http + WebSocket + ファイル監視）
├── public/
│   ├── index.html     # ビューア1ページ（日本語UI）
│   └── viewer.js      # three.js表示ロジック
├── package.json       # deps: ws, chokidar, three
└── test/              # スモークテスト（node:test）
```

- **ビルドレス**: バンドラを使わない。three.js は importmap で
  `/vendor/three/...`（node_modules を静的配信）から ES Modules として読み込む。
  常設ツールなのでビルド工程ゼロを優先する。
- **サーバー**: 素の `node:http` + `ws` + `chokidar`。Express不使用（依存最小化）。

## 起動と使い方

```bash
node ~/dev/mieru/server.js <監視ディレクトリ> [--port 5301]
```

- 監視ディレクトリ省略時はカレントディレクトリ。
- ポートは **5301 固定**をデフォルトとする（既存台帳 443/8443/9443/10443/11443、
  hakogen 5199 と衝突しない。ローカル専用なので台帳追記は不要）。
- Claude Code からの典型フロー:
  1. Claudeが `server.js` をバックグラウンド起動（監視先＝案件の出力ディレクトリ）
  2. Browserペインで `http://localhost:5301` を開く
  3. 以後、Claudeがモデリングコードを修正→STL再生成→ビューアが自動更新

## サーバーの責務

1. **静的配信**: `public/` と `node_modules/three/`（`/vendor/three/` にマップ）、
   および監視ディレクトリ内のSTLファイル（`/files/<相対パス>`）を配信する。
   `/files/` はパストラバーサルを拒否（監視ディレクトリ外への `..` 解決を遮断）。
2. **監視**: chokidar で監視ディレクトリ以下の `**/*.stl` を再帰監視
   （`awaitWriteFinish` で書き込み途中の読込を防ぐ）。
3. **通知**: WebSocket で接続クライアントに
   `{type:"list", files:[{path, size, mtime}]}` を配信。
   追加・変更・削除のたびに全量リストを再送する（差分管理はしない。単純さ優先）。

## クライアント（ビューア）の責務

- **表示**: three.js + STLLoader（バイナリ/ASCII両対応）+ OrbitControls。
- **描画方式**: **オンデマンド描画**。連続 requestAnimationFrame ループは使わず、
  「カメラ操作時」「ファイル更新時」「UI操作時」のみ再描画する。
  （Browserペインはバックグラウンド時に rAF が止まり描画が凍る既知の癖への対策。
  hakogen での実績ある回避策に準拠）
- **UI（日本語）**:
  - ファイル一覧サイドバー: 監視中STLをチェックボックスで表示/非表示。ファイルごとに固定色を割当
  - ビルドプレート: A1 mini 想定の 180×180mm グリッド＋原点表示（表示切替可）
  - 寸法表示: 表示中メッシュ全体のバウンディングボックス寸法（X×Y×Z mm）を常時表示
  - 断面: クリップ平面のスライダー（軸 X/Y/Z 選択式）
  - 表示切替: ワイヤーフレーム、ビルドプレート
  - カメラ: 「全体表示」ボタン（バウンディングボックスにフィット）。更新時は視点を保持
- **更新挙動**: WebSocket のリスト受信時、mtime が変わったファイルだけ再フェッチして
  メッシュを差し替える。新規ファイルはデフォルトで表示ON。

## エラー処理

- STLパース失敗（書き込み競合の取りこぼし等）: 該当ファイルの表示を維持したまま
  サイドバーに警告アイコンを出し、次の変更通知で自動リトライ
- WebSocket切断: 2秒間隔で自動再接続（サーバー再起動に追従）
- 監視ディレクトリが存在しない: 起動時に明確なエラーで終了

## テスト方針

- `node:test` によるスモークテスト:
  - サーバー起動→`/` と `/vendor/three/` 配下が200で返る
  - 監視ディレクトリにSTLを追加/更新→WebSocketでリストが届く
  - `/files/../../etc/passwd` 等のトラバーサルが403/404になる
- 見た目の検証はClaudeがBrowserペインのスクリーンショットで実施（自動テスト化しない）
